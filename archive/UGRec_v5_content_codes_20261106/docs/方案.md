# UGRec v5 方案

最终方案的配置是 `configs/final.json`。它由 v4_2 冻结原版改来：保留内容 AE、HSTU 和一步整流流；去掉速度回归，把排序损失改成源噪声上的混合似然；在 HSTU 输入加内容残差码；评估改为混合概率解码。v4_2 原版仍可用 `configs/frozen.json` 复现。改动的依据见 `experiments/mixture_flow_20261105/REPORT.md` 和 `experiments/representation_structure_20261105/REPORT.md`。

## 一次推荐怎么算出来

物品内容是固定的文本向量（Qwen3-Embedding-4B，2560 维）。自编码器把它压到 128 维，再做逐物品 LayerNorm，得到物品表示 \(z_i\)。

**输入端残差码。** 训练前在原始内容向量上做 3 层残差 k-means，每层 64 类，每个物品得到 3 个码。只用内容，不读交互，与 TIGER、RPG 构造语义 ID 的方式相同。每个码有一个可学习的 128 维向量，初始为 0。历史中的物品进入 HSTU 时，输入是 \(\mathrm{proj}(z_i)\) 加上它 3 个码向量之和。打分用的物品表示仍只是 \(z_i\)。码在运行开始时用精确 fp32 计算，不受 TF32 设置影响，写入运行目录的 `input_codes.npy`，哈希记在 `experiment.json`。

**查询。** 2 层 HSTU 把历史编成条件 \(h\)。锚点网络给出方向，乘 \(\sqrt{128}\) 得到 \(m(h)\)；第 \(s\) 个查询的起点是 \(b_s = m(h) + \epsilon_s\)，\(\epsilon_s\sim\mathcal N(0,I)\)（σ=1，噪声范数与锚点相当）。速度网络在 \(t=1\) 求值一次，查询 \(g_s = b_s - v(b_s, 1, h)\)。

**物品分布。** 每个查询给出全目录 softmax \(p(i\mid g_s)\propto\exp(\cos(g_s,z_i)/0.07)\)。用户的推荐分布是 \(S\) 个查询的混合：

\[
p(i\mid h) = \frac1S\sum_{s=1}^{S} p(i\mid g_s).
\]

## 训练目标

\[
L = -\log \frac1S\sum_{s=1}^{S} p(y\mid g_s) + 0.1\,L_{AE}
\]

- 每个监督位置取 \(S=8\) 个噪声。这是混合模型的边缘似然。逐样本 CE \(\frac1S\sum_s -\log p(y\mid g_s)\) 是它的 Jensen 上界，最优解会让查询忽略噪声；边缘似然让噪声有用处。
- 没有速度回归 MSE。排序损失本身就是“噪声 → 一步流 → 查询 → 物品”这个隐变量模型的似然。
- 目录不超过 2 万个物品时用全目录精确 softmax（`catalog=auto`、`max_exact_items=20000`），超过时用均匀有放回抽样 4096 个负样本的修正 softmax，保留物品上限。
- 每步最多 1024 个历史位置。梯度进入自编码器（历史侧和物品侧）、历史编码器、码向量、锚点和速度网络。
- 局部自编码器损失：每步抽 512 个训练物品，计算重建、余弦、方差和相关正则。

## 解码

每个用户抽 32 个查询，按 \(p(i\mid h)\) 取 Top-K，与训练的似然一致。v4_2 的 L2 最近邻 support 投票不再使用：对按边缘似然训练的模型它在三个种子上都低 0.0016–0.0020。大目录可以对每个查询用 ANN 取 top-20、合并后按混合概率重排；Beauty 上这样得到的 top-10 与全目录完全一致。

## 数据与选模

Amazon Reviews 2014，默认 Beauty，留一法。每条序列的最后一件商品是 test，训练和选模都不读它。验证目标是倒数第二件。

训练窗口：每条序列的第一个窗口监督所有下一件商品，之后的窗口只监督最后一个位置。

每 5 轮在固定的 4096 个验证用户上按 NDCG@10 选 checkpoint。这 4096 人由种子 20261028 一次抽定，不随训练种子改变。训练跑满 40 个 epoch，中途不早停。结束后用选中的 checkpoint 在全部验证用户上再评一次；这个完整验证包含那 4096 人，不是独立测试。

## 结果

以下数字来自实验目录（Beauty，完整验证，test 未读取），不是本目录 `scripts/train.sh` 跑出的。

| 方案 | NDCG@10（三种子） | Recall@10 | 来源 |
|---|---:|---:|---|
| 最终方案：边缘似然 + 残差码 | **.06049 ± .00117** | .10999 | representation_structure，`codes_rawRQ3x64_input*` |
| 同代码对照：边缘似然，无码 | .05879 ± .00110 | .10723 | representation_structure，`control_joint_M1*` |
| 一次前向抽样排序（`matched.json`） | .05742 ± .00063 | – | 本目录 `outputs/Beauty/ugrec_v5_matched_s*` |
| v4_2 冻结原版（`frozen.json`） | .05813 ± .00096 | – | `UGRec_v4_2/docs/v4_2_研究报告.md` |

- 加码相对同代码对照，三个种子的配对差 +.00141 / +.00205 / +.00167，均值 +.00171 ± .00032。
- 全目录精确 CE 是另一项确认过的改进：在三种目标上都比 K=1024 抽样高 .002–.003（mixture_flow 报告）。
- 确定性单查询（逐样本 CE、S=1、全目录）在 mixture_flow 代码下是 .06058 ± .00059，与最终方案持平。最终方案保留随机性，噪声的利用度约为确定性模型的 5 倍，但在留一 NDCG 上没有因此更高。
- 两套实验代码对同一配置有约 .0008 的系统差（mixture_flow 的 G exact 比 representation_structure 的 control 高），原因未查；表中只在同一套代码内比较。
- 确认实验的三个种子在开启 TF32 时拟合码，彼此有 11% 的物品码不同（第一层完全相同）。本目录改为精确 fp32 拟合，码稳定，但与实验里用的码不完全相同。用本入口重跑三种子后，应以新数字替换上表第一行。
- 所有全目录 CE 的组都在第 15 轮前后达到选模峰值，之后过拟合；训练预算没有调。

## 没有采用的方向

均在实验报告中有记录：速度回归 MSE 作为辅助项（精度不变，增加调参）；多步 ODE/SDE 解码和训练；更大噪声与更多样本；hybrid 目录；输出端分块、RPG 式分视角、Matryoshka 前缀、粗码分级 softmax；NeXtVLAD（输入、层间、输出、混合成分）；可学习或实时重聚类的码；接近物品 ID 的细码（RPG OPQ 32×256）。
