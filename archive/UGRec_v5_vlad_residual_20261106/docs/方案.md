# UGRec v5：VLAD K8/S1

默认入口 `scripts/train.sh` 读取 `configs/final.json`。2026-11-06 按用户要求移除内容残差码，采用输出端 VLAD 混合模型。此选择是为了把多簇表示纳入端到端流程，不意味着已有实验确认它优于 control。

## 完整流程

固定文本特征（Qwen3-Embedding-4B，2560 维）→ 在线内容 AE → 逐物品 LayerNorm 得到 128 维物品表示 \(z_i\) → 输入投影 → 两层因果 HSTU。输入端不再有离线 k-means、内容码或码 embedding。

对于位置 \(t\) 的 HSTU 输出 \(u_t\)，基础条件是 \(h_t=\mathrm{condition\_proj}(u_t)\)。VLAD 读取截至当前位置的整段 HSTU 输出：

1. 每个 \(u_i\) 线性扩维：128→256（λ=2），再拆成 G=8 组，每组 32 维。
2. 从扩维特征预测每组到 K=8 个簇的 softmax 分配 \(a_{i,g,k}\)，以及 sigmoid 组门控 \(b_{i,g}\)。有效激活 \(w_{i,g,k}=\mathrm{mask}_i b_{i,g}a_{i,g,k}\)。
3. 每个簇有一个 32 维中心 \(c_k\)，初始化为 N(0,0.02)。计算因果前缀残差及激活量：

\[
r_{t,k}=\sum_{i\le t,g}w_{i,g,k}(x_{i,g}-c_k),\quad
M_{t,k}=\sum_{i\le t,g}w_{i,g,k},\quad
v_{t,k}=\operatorname{normalize}_2(r_{t,k}).
\]

这里 \(x_{i,g}\) 是扩维分组后的特征。前缀包含当前位置；它用于预测下一件物品，不读未来 token。没有 BatchNorm，padding 的激活量为零。簇分配是神经网络预测，不是先做 k-means，也不是直接按到中心的距离分配。

4. 保留每个簇，构造独立条件和混合权重：

\[
h_{t,k}=h_t+Pv_{t,k}+e_k,\qquad
\pi_{t,k}=\frac{M_{t,k}+10^{-6}}{\sum_j(M_{t,j}+10^{-6})}.
\]

\(P\) 是共享的 32→128 投影，权重初始化 N(0,0.02)，偏置为零；簇身份向量 \(e_k\) 初始化 N(0,0.1)。与原探索 `vladmix_K8_S1` 一致，混合版不是零初始化的普通 VLAD adapter，其初始输出不要求与 control 相同。π 的来源是累计激活量（mass），不是预测准确率。

## 查询与物品分布

所有簇共享锚点网络和速度网络，并且对完整物品库打分，不按簇限制候选物品。

\[
m(h_k)=\sqrt{128}\operatorname{normalize}_2(Wh_k),\quad
b_{k,s}=m(h_k)+\epsilon_{k,s},\quad \epsilon_{k,s}\sim\mathcal N(0,I),
\]
\[
q_{k,s}=b_{k,s}-v_\theta(b_{k,s},1,h_k),\qquad
p(i\mid q_{k,s})=\operatorname{softmax}_i(\cos(q_{k,s},z_i)/0.07).
\]

“每簇一个噪声”表示每个历史监督位置、每个簇抽一个新的 128 维随机向量，产生一个查询。默认 σ=1，训练 K=8、S=1，共 8 个查询。

最终混合的是各查询的物品概率，而非查询向量或未归一化分数：

\[
p(i\mid\mathrm{history})=\sum_{k=1}^{K}\pi_k\frac1S\sum_{s=1}^{S}p(i\mid q_{k,s}).
\]

## 训练与梯度

\[
L=-\log\left[\sum_k\pi_k\frac1S\sum_s p(y\mid q_{k,s})\right]+0.1L_{AE}.
\]

- `flow_ranking.draws` 是**每个成分**的训练噪声数，默认 1；`vlad_clusters=8`。`vlad_groups=8`、`vlad_expansion=2`。
- 不加速度回归 MSE，不增加簇分离或均衡正则，不改变原探索模型的目标。
- 梯度进入共享内容 AE（历史侧和候选物品侧）、输入投影、HSTU、condition_proj、VLAD 的扩维/分配/门控/中心、簇投影和身份向量、锚点及速度网络。簇权重也参与反向传播。
- 每步最多 1024 个监督位置。目录 ≤20000 个物品时计算全目录精确 softmax；更大目录使用均匀有放回抽样 4096 个负例的修正 softmax。
- 每步另抽 512 个训练物品计算 AE 重建、余弦、方差和相关正则。

## 解码与 control

验证时 `evaluation.eval_num_samples=32` 是**总查询预算**：K=8 时每簇 4 个噪声样本。先在簇内平均概率，再按 π 混合，最后取 Top-K。总预算必须是簇数的正整数倍，配置和接口都检查，不静默截断。

`configs/control.json` 使用相同模型与训练入口，设置 `vlad_clusters=0`、`draws=8`；只保留基础条件 h，8 次训练抽样，32 次验证抽样。control 不含 VLAD 参数，也不含内容码。

零噪声诊断接口每簇使用一个零向量，仍保留 K 个条件，不等价于总共一个查询。正式验证使用随机噪声，不使用此诊断设置。

## 数据、选模与输出

Amazon Reviews 2014，默认 Beauty，留一法：训练和验证输入截至倒数第三个物品，验证标签为倒数第二个；最后一个 test 标签不用于训练、选模或本次验证。

训练窗口：第一个窗口监督所有下一件物品，之后的窗口只监督最后一个位置。训练 40 个 epoch，每 5 轮在固定种子 20261028 选出的 4096 个验证用户上按 NDCG@10 选模，不提前停止。最后载入最佳 checkpoint，在所有验证用户上计算 Recall、NDCG 和混合分布 NLL。完整验证包含选模用户，不是独立测试。

运行目录保存配置、数据指纹、VLAD 设置、训练和簇诊断日志、最佳 checkpoint、选模与完整验证预测。CUDA 运行额外记录 PyTorch 峰值显存。checkpoint 同时保存 AE、VLAD、推荐模型、优化器、调度器和 RNG；恢复时检查 flow_ranking 设置。

原内容码方案源码保存于 `archive/UGRec_v5_content_codes_20261106/`，已有结果不改写。其带内容码的 checkpoint 不能加载到当前模型，加载时会明确提示使用快照。v4_2 原版与旧抽样排序配置仍保留在 frozen.json、matched.json。

## 实验结论与限制

本入口的本次实测见 [VLAD 混合验证](VLAD混合验证_20261106.md)。旧探索目录 `experiments/representation_structure_20261105/REPORT.md` 的 seed 2024 中，VLAD K8/S1 NDCG@10 为 .05959、control 为 .05946，只能视作持平。它们是历史实验，不替代本次重跑。

原探索还观察到 π 接近均匀、后验责任接近均匀、查询余弦接近 0.92；均匀权重不代表簇已分工。当前实现忠实保留该方案，没有另外加入多样性目标。单标签边缘似然允许不同成分趋同，并不保证多兴趣分离。

VLAD 汇总整段 HSTU 输出，可能补充最终单个 h 没保留的信息；没有引入新的外部数据不等于理论上不可能改善。是否改善应以同入口、同预算对照为准。
