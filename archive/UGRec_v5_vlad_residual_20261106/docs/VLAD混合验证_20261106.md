当前采用输出端 NeXtVLAD K8/S1，移除输入端内容残差码。训练和验证公式见 [方案](方案.md)。

## 实现验证

- v5 的 62 项测试通过，包含因果性、padding、激活量权重、显式混合概率、反向梯度、抽样目录、训练/验证查询预算和 checkpoint 下一步恢复一致性。
- 真实 Beauty 数据 GPU smoke test 通过：4 个更新、验证、checkpoint 保存完成；仅检查流程，指标不用于效果判断。
- 与历史 `VLADMixtureModel` 对齐参数和随机噪声后，训练损失差值 0，32 查询解码的 log probability 最大差值 0。

## 完整实验

GPU 5，Beauty，seed 2024，40 epoch，每 5 轮在固定 4096 人验证子集选模，选中的模型在 22363 名完整验证用户上评估。每组训练每位置总共 8 个查询，验证每用户总共 32 个查询。test 未使用。

| 本次实测方案 | 最佳 epoch | NDCG@10 | Recall@10 | NLL ↓ |
|---|---:|---:|---:|---:|
| control（无内容码、无 VLAD） | 15 | .059463 | .109154 | 8.06249 |
| 移除前的内容残差码 3×64 | 10 | .057452 | .109154 | 7.91324 |
| 当前默认 VLAD K8/S1 | 10 | **.059588** | **.112328** | **7.90581** |

- VLAD − control：NDCG@10 +.000125、Recall@10 +.003175、NLL −.15668。单种子下 NDCG 应视作持平，不能宣称稳定提升；Recall 和 NLL 更好也需要多种子确认。
- VLAD − 移除前内容码方案：NDCG@10 +.002136。这是本次 v5 入口的配对实测，不沿用旧探索目录中 .06087 的内容码数字。旧方案本次用精确 fp32 拟码，原探索的代码和数值设置不同；没有据此定位差异原因。
- 当前 VLAD 与历史探索 K8/S1 的 seed 2024 完整验证结果一致（NDCG .05958782、Recall .11232840），control 也一致（NDCG .05946320）。不仅完成参数对齐的单批检查，也复现了完整训练指标。

## 复现命令与文件

从 `UGRec_v5` 运行：

```bash
GPU_ID=5 bash scripts/train.sh --run-id ugrec_v5_vladmix_K8_S1_s2024_20261106
GPU_ID=5 bash scripts/train.sh --config configs/control.json --run-id ugrec_v5_control_s2024_20261106
```

以上 run id 已存在，重新运行必须换新名字。两份配置只有 VLAD 开关、每成分抽样数及 run id 不同，其他设置相同。`final.json` 默认 K8/S1，`control.json` 为单条件 S8。

移除前方案是在改动源码之前启动，用保存在 `archive/UGRec_v5_content_codes_20261106/configs/final.json` 的原配置跑完。该快照保存完整原实现。旧内容码 checkpoint 的 NLL 另用快照实现补算，32 查询的预测与原始 `full_flow.npz` 逐元素一致；补算记录是运行目录的 `nll_audit.json`。

所有组的数据指纹（原始内容、训练序列、物品顺序）相同；各组均完成 4040 个训练更新。结果汇总为 `outputs/vladmix_validation_20261106.json`。
