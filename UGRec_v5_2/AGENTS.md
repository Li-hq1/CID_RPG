# UGRec_v5_2 执行约定

先读 `README.md`、`docs/方案.md`、`docs/实验计划.md` 和 `docs/验收记录.md`，遵循用户全局科研规则。

- 这是用户授权的新目标/梯度路线，不属于 v5_1 调参白名单。不得修改 UGRec_v5、UGRec_v5_1 的源码、配置或结果；公共 cache 只读，禁止跨版本运行时导入。
- 历史 CE 学排序，CFM MSE 学速度；FM 输出不接 CE。回归源点、目标与桥状态停止梯度。默认 parallel/tail 的 MSE 不进入 AE、共享主干、排序尾部或排序头。
- `mse_scope=shared` 仍须阻断 AE 的全部 MSE 路径：历史输入、物品目标、源点。不能只修改一个 detach 而遗漏另一条路径。
- 双尾部不证明消除了全部任务冲突：AE/共享表示随 CE 变化，全局梯度裁剪也会耦合步长。零初始化时首步内部梯度可能为零，不能误判断图。
- 探索仅 seed2024，逐轮写假设并选必要对照；不自动执行网格、多种子或四数据集完整训练。先查排序头是否可用，再查 FM 对先验的增量。
- 时间方向、速度符号、训练/推理噪声保持一致。`sampling_steps` 是速度网络调用次数，`num_sampling_steps=sampling_steps+1` 是网格点数。
- 按固定验证用户的 NDCG@10 选模，再做全 validation 审计；不访问 test。smoke/max_steps/低预算结果须标为工程检查，不能变成 benchmark。
- 每次独立输出目录拒绝覆盖，保存源码快照/指纹、展开配置、数据指纹、日志及联合 checkpoint。代码修改后重建匹配实验，不补旧结果。
- 改动后运行 `bash scripts/test.sh`，模型/数据接口再做真实缓存短程检查。使用 GPU 前查资源，不中断其他任务。
- 2026-11-06用户追加授权初步实验：先Beauty/seed2024的纯CE匹配对照与串联CE+CFM，区分FM直接收益和MSE对CE的间接作用。依证据决定是否追加双尾部对照，不自动扩大矩阵。
- `fm.mse_weight=0` 仅为明确标记的CE-only对照，须使用ranking选模/预测，不能报告为已训练FM。保留相同前向/RNG调用以匹配训练随机流，不拿该冗余计算的耗时代表精简CE部署成本。
- 最新研究取舍见 `docs/初步实验分析_20261106.md`：三组Beauty/seed2024初筛均无FM增量，暂不扩展双尾部，保留纯CE为研究参照。`final.json`是保留的原入口，不能因其名字自动恢复双尾部实验。冻结CE对照额外40epoch，不冒充等总预算系统比较；研究脚本及只读诊断独立保存。不要将小样本负梯度余弦、样本差异或MSE下降写成互补性或已收敛的证明。
