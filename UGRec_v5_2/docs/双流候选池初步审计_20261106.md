# 双流候选池：缓存预测的初步审计

## 问题与协议

检验一个窄问题：FM 是否能在 CE 的 top-10 之外补充命中，使它作为额外候选源有价值？复用 Beauty/seed2024 冻结 CE checkpoint 的全 validation 预测及其 32-draw、4-step FM 聚合预测，不重新训练、不重新推理、不访问 test。对两个 top-10 列表取并集，并按固定 CE/FM 名额构造长度为10的列表；不足时按 CE 列表再按 FM 列表的原排序补齐。脚本为 `research/dual_candidate_audit.py`，输出保存在 `outputs/dual_candidate_audit_20261106/summary.json`。

这是基于已保存聚合概率 top-10 的候选池诊断，不是逐次 FM 样本的 item 投票。因而它能检查当前两个排名列表的互补性，不能验证“32次独立采样后提取不同 item”的完整部署方案，也不能据此确定线上候选融合策略。

## 结果

全 validation 22,363 人。CE top-10 命中率/Recall@10 为 11.12%，FM top-10 为 8.47%。二者并集覆盖 12.87%，FM 单独补到 CE 未命中用户 392 人（+1.75 个百分点）；CE 单独命中而 FM 未命中 984 人。存在有限池级补充，但两者质量并不对称。

| CE 名额 / FM 名额 | Recall@10 | NDCG@10 |
|---:|---:|---:|
| 10 / 0 | 0.11117 | 0.06041 |
| 8 / 2 | 0.11041 | 0.06019 |
| 6 / 4 | 0.10848 | 0.05956 |
| 5 / 5 | 0.10643 | 0.05879 |
| 4 / 6 | 0.10312 | 0.05758 |
| 2 / 8 | 0.09717 | 0.05468 |
| 0 / 10 | 0.08469 | 0.04642 |

配额列表的前五个位置在 CE 名额不少于5时完全由 CE 占据，因此 Recall@5/NDCG@5 与 CE 相同；加入 FM 后，top-10 指标随 FM 名额增加而下降。固定十个展示位时，本 checkpoint 上没有发现能改善排序质量的 FM 配额。

## 研究判断

结果支持区分“候选召回”与“最终排序”：FM 聚合 top-10 能提供 CE top-10 之外的额外命中，但目前较弱的 FM 排名会损害最终 top-10。若下一步要继续检验双流，需要真正从各个 FM 样本解码 item 候选，再按用户任务评估固定 CE 精排名额和额外召回位；不能只把 FM 列表替换 CE 列表，也不能把样本差异直接当作有用多样性。当前全 validation 同时用于既有选模，且只有单种子，结果仅作探索趋势。
