# UGRec_v3 方案：表示与条件生成的联合优化

> 本文于 2026-10-28 根据当前实现与研究记录整理。REPA-E 用作统一表示/生成训练的启发；本文不声称完整复现 REPA-E 的具体方法。

## 研究问题

v2 在推荐训练前冻结 AE，无法让内容压缩适应行为条件。v3 将 AE 与推荐模型纳入同一训练过程，建立可控制梯度路由、可恢复、可搜索的训练基础，再检验任务相关信号是否能够改善压缩几何与推荐效果。

已有观察是联合训练与两阶段效果接近，当前一轮参数搜索未优于默认基线。本阶段保留这一结论，不将“训练联合”本身当作已经有效的改进。

## 网络与归一化

输入仍是冻结的高维内容 embedding。AE 产生低维 latent，逐物品 LayerNorm 后进入序列模型和 RF 目标空间；Transformer/HSTU 产生用户兴趣条件，RF 生成低维物品表示。候选库必须由当前 AE 与相同归一化重新编码。

当前 AE 随机初始化，输入均值与全局 RMS scale 仅用推荐训练物品拟合。没有默认加载 v2 best artifact 的初始化流程；历史预训练初始化、fixed/EMA normalization 与 bridge 结构已归档。AE 采用默认 MLP 2560→1024→512→128，序列与 RF 基本结构沿用前两版。

## 交替优化与梯度连接

每个训练步包含两个独立 optimizer 时间线：

1. **AE 更新**：冻结推荐模型参数；抽取训练物品，优化重建、cosine、variance、correlation 和可选 batch relation。若启用 InfoNCE，以 RF 的 clean-state 估计作预测、当前表示作物品候选，加入 `contrastive.weight × L_InfoNCE`。计算图可以穿过被冻结的推荐网络流向 AE，但不更新推荐参数。
2. **推荐更新**：清空梯度，用更新后的 AE 产生表示并断开 AE 图，仅以 RF velocity MSE 更新序列模型、输入/条件投影与 RF 网络。

```text
AE step:   ∇φ [L_AE + λ L_InfoNCE]，推荐参数冻结
Rec step:  ∇θ L_RF(stopgrad(AEφ(e)))，AE 不更新
```

因此本版是交替联合训练。默认关闭 contrastive 时，AE 仅由内容目标训练，RF 损失不会自动反传 AE。不能将当前默认配置描述成“RF 端到端更新压缩器”。开启 InfoNCE 才引入当前保留的推荐相关 AE 更新通路。

对比学习默认温度 0.04、权重 0.01、最多 1024 query、64 个负样本。RF 使用所有有效位置；query 上限仅限制对比项，不截断 RF 监督。双向更新、旧 bridge loss 与旧调度字段不属于当前支持的配置。

实现位置：`joint_training/model.py`、`contrastive.py`、`normalization.py`、`training.py`。

## 表示一致性与恢复

每次 AE 更新后将候选库标为过期；评估前用当前 AE 重建完整物品 latent，禁止使用上一轮 AE 的旧库。checkpoint 同时包含 AE 与推荐模型、两个 optimizer/scheduler、训练步、选模状态、随机数和数据源身份；最终导出 catalog_latents 便于追溯，不能单独拿导出特征搭配另一个 checkpoint。

加载时核对内容 embedding、item 顺序、训练样本源、模型与优化设置。恢复训练还检查预算与评估协议，避免拿不同采样策略的验证分数接着早停。旧模型结构不通过重命名配置强行恢复。

## 默认训练与对照

AE 学习率 `3e-5`，推荐学习率 `5e-4`；AE batch 512、推荐 batch 256；分别 warmup 5%/10% 后 cosine decay；默认每步各更新一次。推荐 100 epochs，每 5 epochs 验证，best `ndcg@10`，评估沿用 32 次采样、每次初始 1 个候选、L2 support。

| 对照 | 研究目的 |
| --- | --- |
| v2 冻结 AE / v3 交替 AE / 本版 PCA | 区分表示更新、生成骨架与初始化差异 |
| contrastive off / AE-only InfoNCE | 判断推荐相关 AE 信号的收益 |
| 不同 AE/推荐学习率与更新频率 | 检查变化的目标分布与优化平衡 |
| Transformer / HSTU | 检查主干差异是否影响联合优化 |

本版当前随机 AE 初始化与 v2 预训练冻结 AE 不同；比较时应显式报告初始化与训练预算，不能将所有差异都归因于联合优化。

## Optuna 搜索协议与保留问题

搜索空间位于 `joint_training/search_space.json`，包含训练轮数、batch、AE 学习率/正则/目标权重、推荐学习率/正则、InfoNCE 温度与权重等。TPE 搜索、MedianPruner，可入队默认基线；每个 trial 使用独立 run ID 与输出目录，同 study 名可续搜。

当前实现以验证集选择 best checkpoint、以验证分数执行剪枝，已完成 trial 的 objective 是该 checkpoint 的**测试集** `ndcg@10`。因此测试集参与了超参选择，研究报告应如实披露；若后续改为验证 objective，应开启新 study 并重新评估，不能混合历史值。

已有 `load_study` 路径没有显式传入配置中的 sampler/pruner；续搜时可能使用 Optuna 默认 pruner warmup，从而与保存的搜索设置不同。历史 Memory 记录过这类现象。本次整理保留代码与结果，后续若修正，应单独记录协议变更并用新 study 验证。

Memory 中远端 Beauty 53-trial 搜索记录约 15.6 小时，最好仍为 trial 0 基线（记录的测试 ndcg@10 0.0319、recall@10 0.0568）；该数据库不在当前本机，以上来自历史记录，不是本次读取数据库或复测得到的结果。

## 阶段完成边界

本版交付可独立运行的联合训练、评估、恢复、诊断与搜索实现，建立后续优化基础。当前不宣称已优于两阶段或默认参数；目录整理验收使用单元测试和小样本实际缓存检查，不替代正式多种子推荐实验。
