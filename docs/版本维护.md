# 版本维护约定

一个版本对应一个可明确描述的研究阶段。阶段内的参数与实现修正可继续在原版本迭代；当表示方式、训练目标或模块梯度连接发生主要变化时，复制出新的 `UGRec_vN`，先补充方案再实现。

1. 每版保留自己的完整算法代码、数据处理逻辑、默认配置、脚本、测试与 `outputs/`。禁止通过修改 `sys.path` 或导入另一版模块来复用算法。
2. 共用原始数据、预训练文本模型、原始 embedding 缓存和 Python 环境；派生样本缓存必须包含能区分样本策略的键。跨版本比较时记录实际命中的缓存。
3. 独立 AE 权重和特征导出归其训练版本；联合模型 checkpoint 必须同时保存当前 AE、推荐模型和训练状态。新版本需要旧 AE 初始化时，应显式记录来源与 artifact ID，并保留自身运行所需的副本。
4. 所有新输出写在所属版本的 `outputs/` 下。`RUN_ID` 区分数据集、编码器、压缩方式、采样协议和消融变量；恢复已有实验用 resume，不复用名字混写不同方案。Git 不跟踪 `outputs/`、`ckpt/`、`cache/`、`.venv/`、`experiments/`、`FMRec/`，以及权重、`.pkl` 和训练日志。
5. 方案文档记录研究目标、公式、梯度连接、默认值、消融设计和已知限制；实验结论必须区分研究者观察、保存日志的数值和本次复现实测。
6. 比较版本时固定文本特征、数据划分、训练预算、监督策略、随机种子、验证选模规则、采样次数、候选数、距离和聚合方法。改变评估采样会改变召回与耗时，应单独报告。
7. 修改一版后在该目录运行 `bash scripts/test.sh`；涉及模型或数据接口时再做对应的真实缓存小样本检查。无改动的旧版无需跟随新版本更新。
8. `archive/pre_ugrec` 和 `outputs/history` 是参考资料，不属于当前支持的运行入口。历史结构缺失时明确标记，不能仅重命名字段就宣称恢复兼容。

v1 至 v3 按研究逻辑从同一份现存工作区拆分；它们不是各历史时刻的 Git checkout。v4、v4_1、v4_2 保留各自的实验记录。v5 从 v4_2 的冻结配置抽出原版方案，作为后续实验起点；抽出时没有重训，也不改 v4_2 的实现和结果。没有足够证据时，不宣称旧实验与当前默认基线具有完全相同的历史行为。
