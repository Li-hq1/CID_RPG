# UGRec_v5_1 调参计划：按数据集、按当次方向自动迭代

本次规则修订日期：2026-11-08（America/Los_Angeles）。本规则替代原来的“起点校准 → 共用结构/容量 → 固定结构后调专用参数”流程；旧实验的时间、配置、结果和 decision 保留原记录。此次仅修改文档需求，不启动调参。

## 核心问题与边界

v5 control 的研究路线维持不变。调参要解决的是：对当前指定的数据集，在用户当次给出的方向内，哪些设置能改善该数据集的推荐表现，已有曲线和诊断是否支持这一改动。先明确瓶颈和假设，再选择候选；不能以“可能涨点”为理由叠加无关模块。

默认候选数据集仍为 Beauty、Sports、Toys，CDs 不自动恢复。**每次以一个数据集为独立调参单位**，不要求多个数据集使用同一套结构、容量或优化参数。用户指定多个数据集时，逐个独立推进和记录，不自动为其他数据集补跑。

不再区分“必须先统一调的参数”和“之后才能独立调的参数”。学习率、loss 权重、AE/HSTU/Flow 的已有模型参数，都可以在用户指定的方向内针对当前数据集调整。取消 Beauty 起点必须不变、结构候选必须三数据集共同评价、专用参数阶段必须锁死结构等旧阶段要求。

内容 AE、因果 HSTU、历史锚点加高斯噪声、一步 Euler、噪声边缘似然和混合概率解码仍作为默认机制。调整现有 loss 的权重不等于新增 loss；新目标、新模块、数据处理或推理预算变化不由一句普通调参方向自动授权。

## 每次对话如何确定任务

用户后续给出当前数据集和大致调参方向，agent 据此自动细化参数、候选值、对照和迭代顺序，不要求用户逐个指定数值或确认每个常规候选。

- 例如“Beauty，调学习率和 loss 的比例”：围绕 AE/推荐器学习率及现有 AE 正则与推荐目标的相对权重迭代，先用证据区分步长与损失平衡的影响；不自行加入结构搜索。
- 例如“Sports，调模型的参数”：根据当前瓶颈，从已有 AE/HSTU/Flow 的深度、宽度、投影或 norm 参数中选择最有信息的一条轴；不自动把所有模型参数做网格搜索。

数据集或方向已由本轮或仍适用的对话上下文明确时直接执行。缺少且无法推断的必要信息再简短询问，不自行挑选数据集或恢复旧阶段。用户后续改变方向时，以最新要求为准，沿用该数据集已采用的配置；不需要先完成旧方向或为其他数据集找到同样改进。

## 单个数据集的迭代闭环

1. **确定范围与起点。** 记录目标数据集、用户原始方向及其对应的可调字段、固定条件、训练预算和评估协议。读取该数据集已有配置、结果和曲线，确定本轮 parent 与固定 reference。
2. **提出可区分的假设。** 说明当前瓶颈、为何选这项改动，以及什么结果支持或否定它。优先一个主要变化；必要的耦合参数一起调整时说明机制联系及归因限制。
3. **执行有限候选。** 根据当前方向和证据选择少量候选，不自动穷举、不默认 Optuna 大搜索。探索固定 seed2024，可比实验保持其他条件一致。先核对资源和工程正确性，再执行正式训练与完整 validation audit。
4. **按当前数据集决策。** 对比该数据集的 NDCG@10、学习动态、复杂度、时间和显存，记录采用、保留、拒绝或证据不足。候选不能因其他数据集表现较好而晋级，也不因没有运行其他数据集而失去有效性。
5. **更新记录并决定是否继续。** 在同一方向内根据证据继续有限邻域迭代。方向失效、连续两次没有信息增益或达到用户预算时停止，保留现有可解释配置。完成该方向不自动切换到另一方向、另一个数据集、多种子或 test。

每个数据集单独维护已采用配置、parent、reference 和待验证问题。reference 在本轮方向内固定，parent 可随已采用候选推进；方向切换时如需重设 reference，明确记录原因和来源。跨数据集汇总仅用于展示，不作为联合晋级条件。

## 当前可继承的结果

目前可用的起点是 `structure_hstu_depth_1_s2024` 中各数据集已审计的结果：HSTU 一层、Flow 两块、AE `[512,256]→128`，Sports recommender LR=0.0005，其余为 0.001。Beauty/Sports/Toys 全量 NDCG@10 分别为 0.06049500 / 0.03574440 / 0.05625818。

后续分别从目标数据集对应的配置和测量继承，不要求三个数据集此后保持一致。该 campaign 的旧四数据集 `decision.json` 仍为 reject；不改写历史决定，不把已有测量计作本次新实验。若运行代码、数据或评估协议发生影响可比性的变化，先建立当前数据集的匹配对照。

## 选模与稳定性

具体口径见 [指标遵循](指标遵循.md)。主指标仍为当前数据集的完整 validation NDCG@10；默认训练 40 epoch、batch 256、训练/验证噪声 8/32。用户方向包含 epoch 时可以声明更长的 5 的倍数预算，选模用户与随机种子保持一致，不用更换过滤规则拼分。跨数据集均值及“任一数据集不得下降超过 2%”只用于解释历史共享实验，不再决定本轮单数据集的取舍。

探索和初筛只用固定单种子，结果只作趋势证据。最终方案明确冻结后，才对该数据集的最终方案和关键对照显式安排匹配多种子，报告逐种子、均值和波动；不自动开启种子扫描。test 仍不用于调参，也不在本轮结束后自动评估。

## 每轮记录要求

记录目标数据集、用户给出的方向、具体假设、可调参数与候选理由、固定条件、parent/reference、seed、展开配置、运行及审计结果、指标变化、资源成本、采用与否、下一步或停止理由。结果目录不可覆盖；旧实验、失败和 OOM 如实保留。工程 check 与 smoke 不作为 benchmark，复用结果要注明实际测量来源。

## 执行器适配与当前状态

2026-11-09 起，新 campaign 可以声明 `target_datasets`、`selection_rule=target_ndcg10` 和 `epochs`。只调度、审计和比较列出的那一个数据集；数值晋级要求该数据集完整 validation NDCG@10 高于固定 reference，且不低于 parent。不计算三项均值，也不使用 2% 护栏。`epochs` 省略时仍是 40；写明时必须是不小于 40 的 5 的倍数，审计按这个声明核对完成轮数和更新数。短于 40 epoch 仍然不能作为 benchmark。

未写这些字段的旧 spec 仍展开 Beauty、Sports、Toys，并沿用均值/2% 护栏。历史 campaign 按各自 manifest 读取，不回写。模型、损失、噪声和评估预算仍不能从 spec 里改掉。

Beauty 的慢收敛候选 `beauty_hstu3_rec_lr_half_ep80_s2024` 已 reject。另有一个尚未启动的 Optuna 筛选，见 [Optuna搜索](Optuna搜索.md)。它只比较固定 4096 人的选模 NDCG@10，不能代替完整 validation 的 campaign 决策。
