# 指标遵循与结果审计

本次规则修订：按数据集独立调参，方向以用户当次对话为准。旧共享阶段与跨数据集晋级规则仅保留历史解释意义，详见 [调参计划](调参计划.md)。

## 数据与训练协议

AmazonReviews2014：Beauty、Sports_and_Outdoors、Toys_and_Games、CDs_and_Vinyl。使用当前共享缓存的预处理数据及原始 Qwen3-Embedding-4B 2560 维向量，不重新过滤或改 split。每个序列最后一项为 test，倒数第二项为 validation，前缀为 train。共享 JSON 文件物理上包含最后一项，但本入口在 ID 映射前先切掉它，不取 test target、不评价它、不据此选方案。AE 输入均值/尺度只拟合训练交互出现过的物品；目录仍包含该数据集的全部物品，与 v5 协议一致。

最大历史 50。训练首窗监督全部后继，之后每个滑窗只监督最后一个后继。每次只训练目标数据集；每数据集的“40 epoch”不是同更新数，必须记录窗口数和实际更新数。当前范围为 Beauty、Sports、Toys，CDs 的协议描述只供历史复现，不表示恢复其训练。

正式默认：40 epoch，batch 256，单种子 2024，AE batch 512，最多 1024 个监督位置，训练噪声 8，验证噪声 32，固定噪声尺度 1。用户当次方向包含 epoch 时，campaign 可以声明更长的预算：整数、不小于 40、并且是 5 的倍数。审计核对的是这个声明的轮数和对应更新数。短于 40 epoch、或跑满之前按耐心停掉，都不能作为 benchmark。目录 ≤20000 用精确 softmax；CDs 使用 4096 个均匀有放回负例的修正 softmax。验证始终全目录精确概率、按噪声的预测概率平均，禁止用采样候选集或 ANN 替代。

## 选模、比较、报告分别是什么

1. **同一 run 选 checkpoint**：每 5 epoch 在固定的最多 4096 名验证用户上计算 NDCG@10；抽取顺序由 NumPy default_rng(20261028) 固定。相同分数保留先达到的 checkpoint。训练不中途按耐心裁剪，跑满该 campaign 声明的 epoch；未声明时是 40。
2. **候选比较**：载入所选 checkpoint，先重算并核验选模预测，再评价该数据集全部验证用户。已有模型结构参数、优化参数与 loss 权重均使用该数据集的完整验证口径；无需等待其他数据集 audit。
3. **最终稳定性**：该数据集的最终配置冻结后，显式指定多个种子，报告逐种子值、均值和样本标准差（ddof=1）；关键对照使用相同种子。仅一侧多种子时，只能说该侧稳定性，不能声称公平的多种子优势。
4. **test**：本版调参入口不提供 test 评估，也不会在全部验证后自动评估 test。最终确定方案后另行安排一次固定配置的测试集评估；不得反过来调整参数。完整 validation 包含选模用户，是调参使用的数据，不是独立测试集。

评估噪声种子固定 20261028，训练 RNG 在评估前后保存并恢复。评估 batch 固定 32；不能为了分数在候选间改变 batch/种子/MC 预算。分块 logits 在生成全部噪声查询后计算，不改变完整 softmax 分母和噪声样本；浮点求和次序可能产生容差内差异。

## 指标与单数据集选择规则

主指标 **目标数据集完整 validation NDCG@10**。同时记录 NDCG@5、Recall@5、Recall@10、NLL。leave-one-out 为单个相关物品，Recall@K 等于命中率；NDCG 命中时为 `1/log2(rank+1)`。候选是物品 1..N，padding 0 不参与；沿用 v5，不屏蔽历史物品。改变重复物品过滤政策必须另立协议，不与本轮结果混排。

对当前数据集 d 与本轮固定 reference b，记录绝对值、绝对差和 `r_d = NDCG10(candidate,d)/NDCG10(b,d) - 1`，并对照直接 parent 判断本轮改动是否有效。新候选完成该数据集的完整训练与 audit、主指标优于 reference 且不低于已采用 parent 时，才具备数值晋级资格；同时还要说明问题对应关系、可归因性、复杂度、显存/时间与取舍。无收益或证据不足时保留已有配置，不强行宣布晋级。只含一个目标数据集的 campaign 使用 `selection_rule=target_ndcg10`，不计算跨数据集均值，也不使用 2% 护栏。

不再要求共享结构、不计算用于联合晋级的三数据集均值，也不使用“任一数据集下降不得超过 2%”作为新实验门槛。其他数据集不补跑，不参与当前数据集的取舍。跨数据集汇总仅展示各自结果；不能用别的数据集改善抵消当前数据集下降。

固定单种子的微小差异只作趋势证据，不等于稳定提升或统计显著。平均值或小数差距不能代替机制解释；差异很小且证据不足时优先保留简单、已有验证的方案。若用户明确以压缩或成本为目标并接受效果取舍，应事先写清该数据集的门槛和预算，不把降分记录成效果提升。

各数据集分别维护采用配置与 parent/reference。本轮方向内 reference 固定；parent 随已采用候选推进。切换方向时可将已采用配置设为新的 reference，但须记录切换理由与实际来源。影响可比性的代码/协议变更需重新建立该数据集的匹配对照；训练与评估预算须匹配。

当前可继承 `structure_hstu_depth_1_s2024` 的 Beauty/Sports/Toys 对应已审计结果，各自可继续独立调整。旧四数据集及三数据集 campaign 的均值、2% 护栏、decision 和时间原样归档，包括该 campaign 的四数据集 reject；不按新规则回写历史。CDs 不进入新实验，除非用户后续明确要求。

## 溯源和不可混用项

campaign 清单记录 spec、parent/reference、假设、理由、UTC 时间、Python 路径/版本、CUDA 可见设备、源码逐文件 SHA256 和源码快照。每个 run 记录最终展开配置 SHA256、内容向量/物品顺序/train/history/validation target SHA256、用户/物品/窗口数、选模索引 SHA256、参数量、峰值显存、逐轮损失/采样诊断/验证指标、实际更新数、最佳 epoch、checkpoint 及验证预测。

`source/` 是准备时的独立代码副本；执行时要求当前代码指纹仍匹配。准备后修改代码需新建 campaign，不能用新代码续跑旧清单。每次执行前重新核对数据指纹。新流程要求只校验和调度目标数据集；历史 manifest 的其他数据集指纹保留作溯源，不要求为本轮访问其数据或启动训练。可复用目标数据集配置、代码和协议均匹配的父实验，保留原配置哈希及来源清单哈希；来源在表中标明，不算额外一次重复验证。`summary.json` 保存机器可读结果，`summary.md` 保存可读表格，`decision.json` 保存不可覆盖的取舍及下一假设。source/config/manifest 的指纹用于可靠溯源，不是对恶意篡改的密码学签名。

未完成本轮声明的目标数据集训练和审计、NaN/Inf、配置不匹配、数据指纹漂移、checkpoint 重载不一致、训练短于该 campaign 声明的 epoch、缺完整 audit 均不能成为 benchmark。未声明时，这个长度仍是 40 epoch。`check`、`smoke_test`、`max_steps` 短运行只验工程，不报为最终效果。失败/OOM 如实记录，原文件保留；禁止填补缺失结果、借旧实验数值充本次实测或跨版本拼一张“已复现”表。

以上是新流程的指标与审计需求。现有执行器仍实现旧三数据集汇总和联合晋级，后续执行前需适配，不能将旧 summary/decide 的自动结论当作已经符合新规则。
