# 参数接口与结构消融

## 原始 control 结构和默认值

下图及表格数值是原始 control 默认值，不等于当前已采用配置。当前起点来自 `structure_hstu_depth_1_s2024`：HSTU 一层、Flow 两块，Sports recommender LR=0.0005；后续分别继承目标数据集的配置。

```text
Qwen 2560 → AE [512,256] → latent 128 → 物品 LN
  → input_proj: Linear(128,128) → LN
  → HSTU: 2 层，4 heads，hidden/head=32，attention/head=32
  → condition_proj: LN → Linear(128,128) → h
      ├→ ranking_head: Linear(128,128) → L2 normalize × sqrt(128) → + ε
      └→ flow cond_embed: Linear(128,256) → + time embedding
             ↓ AdaLN 速度网络：width=256，2 residual blocks
      一步 Euler → 每个噪声的目录概率 → 概率平均
```

HSTU 不是 Transformer FFN，`n_inner`、`embd_pdrop`、`attn_pdrop` 等兼容字段不作为 HSTU 调参维度。物品 latent LN、HSTU 内部规范化、Flow AdaLN 是固定机制；本轮 norm 接口只针对明确列出的过渡或 MLP 位置。

## 模型参数：按目标数据集独立调整

以下已有模型参数可在用户当次指定的方向内，对目标数据集独立调整，不要求其他数据集同步修改或评价。底层字段仍使用 `section.field` 命名。旧执行器将其放入 `spec.shared` 并强制全组展开，这是待适配的实现限制，不再是研究规则；不能把单数据集结构需求直接套入旧 shared 模板执行。

| 参数 | 默认 | 本轮用途 |
|---|---|---|
| `ae.architecture` / `ae.hidden_dims` | mlp / [512,256] | AE 结构及隐藏深度；linear 已有实现，采用前说明与压缩瓶颈的关系 |
| `ae.latent_dim` | 128 | AE 压缩维度；可先比较 64/128/256，逐次选一项，不自动穷举 |
| `ae.hidden_norm` | none | none / layer；仅 AE 隐藏层，Linear 后、GELU 前，encoder/decoder 一致 |
| `recommender.n_embd` / `n_layer` / `n_head` | 128 / 2 / 4 | HSTU 宽度、深度和 heads；宽度必须能被 heads 整除 |
| `recommender.hstu_hidden_dim` / `hstu_attention_dim` | 32 / 32 | 每 head 的值/注意力宽度，attention 维度必须为偶数 |
| `recommender.diffloss_w` / `diffloss_d` | 256 / 2 | AdaLN residual MLP 宽度/块数；加深 2→3 需单独验证 |
| `recommender.input_projection` | linear_norm | linear_norm / linear / norm / identity，定位 AE→HSTU 过渡 |
| `recommender.condition_projection` | norm_linear | norm_linear / norm / linear / identity / mlp，定位 HSTU→Flow 条件过渡 |
| `recommender.condition_mlp_depth` | 1 | 仅 mode=mlp 有效；线性层总数，末层不加激活；比较 1/2/3 不自动连乘 |
| `recommender.condition_mlp_norm` | none | 仅 mode=mlp 有效；none / layer，每个线性层后加 LN，包含末层；LN eps=1e-8 |
| `recommender.anchor_projection` | linear | linear / identity，作用于历史锚点分支 |
| `recommender.flow_condition_projection` | linear | linear / identity，作用于 Flow 网络 cond_embed |

删除 input 线性层或 anchor 线性层需要 `ae.latent_dim == recommender.n_embd`。删除 Flow cond_embed 需要 `n_embd == diffloss_w`。不能在维度不同时暗中补另一个 Linear。若先改宽度以实现等维，必须先训练同宽度且保留 Linear 的匹配对照，再移除 Linear，避免把宽度变化误归因于层的删除。

`condition_projection=mlp, depth=1, norm=none` 为单线性，与 `linear` 语义相同但 state_dict 键不同；不作为两个独立候选。默认 `norm_linear` 是前 LN，MLP norm 是后 LN，比较时必须明确位置，不能把二者统称为“加 norm”。无效的 MLP 字段组合直接报错。

## 优化与 loss 比例参数：同样按目标数据集调整

| 参数 | 起点 | 调整逻辑 |
|---|---:|---|
| `recommender.lr` | 0.001 | 按本轮方向和学习曲线选择步长候选，如 ×0.5 或 ×2，不自动穷举 |
| `ae.lr` | 0.0001 | 按本轮方向及 AE/主任务动态选择；可单独调或检验整体学习步长，说明归因 |
| `recommender.weight_decay` / `ae.weight_decay` | 0.01 / 0.0001 | 收敛与泛化差异驱动，不先铺网格 |
| `recommender.warmup_ratio` / `ae.warmup_ratio` | 0.1 / 0.05 | 初期优化不稳时检查 |
| `recommender.hstu_output_dropout` / `hstu_attention_dropout` | 0.1 / 0 | 仅在过拟合证据下调整 |
| `flow_ranking.temperature` | 0.07 | 每数据集单独调，直接控制目录 softmax 尺度；NLL 只作诊断，主目标仍是 NDCG@10 |
| `flow_ranking.local_weight` | 0.1 | 现有 AE 正则与推荐目标的相对权重；“调 loss 比例”默认对应此项，结合损失/梯度诊断 |

模型参数与上述优化/loss 参数不存在先后阶段限制，Beauty 也可独立调整。用户说“调学习率和 loss 比例”时，围绕 AE/推荐器学习率及 `flow_ranking.local_weight` 自动选择候选；说“调模型参数”时，从已有模型字段中按瓶颈选择有限对照。用户已说明其他现有 loss 权重时以其要求为准。不得把调现有权重扩展成新增损失，或自行加入当次方向外的参数。多个数据集的模型、配置和决策分别记录。

## 固定项与执行接口

默认固定：control、一步 Euler、history prior、σ=1、边缘似然、train draws=8 / eval draws=32、目录阈值 20000、负例 4096、max_queries=1024、训练 batch=256、40 epoch、50 长度历史、Qwen 内容向量、选模用户数和评估协议。用户方向包含 epoch 时，可以在 spec 里写 `epochs`（整数、至少 40、5 的倍数）；它不是 `datasets` 里的补丁。`target_datasets` 加上 `selection_rule=target_ndcg10` 时只展开列出的一个数据集。用户给出的方向授权相应已有参数的常规迭代；新增 noise/draws/采样/过滤规则/损失分支/新模块不由普通调参方向隐含授权，确需超出范围时先明确用户要求并同步白名单和协议。`--set` 是底层调试接口，正式结果只能由 campaign 的白名单展开生成。

`prepare --mode check` 只将更新数减为 2、batch 减为 8、max_queries 减为 16、AE batch 减为 16、验证用户减为 8；保留原结构、完整真实目录、train/eval draws 和 exact/sampled 切换，不使用缩小维度的 smoke model。工程 check 与正式 benchmark 结果互相隔离，不能作为父对照混用。

实现入口：`tuning/schema.py`（作用域和类型检查）、`tuning/campaign.py`（准备/执行/审计/汇总/决策）、`run.py`（训练/选模/重载验真）、`models/projections.py`（过渡结构）、`joint_training/search.py`（Optuna 筛选）。新流程从目标数据集的父实验展开配置，保留其模型与优化设置。单数据集调度、声明的 epoch 和 `target_ndcg10` 已接到 schema 与 campaign；旧 spec 的三数据集路径保留。Optuna 的当前空间见 [Optuna搜索](Optuna搜索.md)，它不写入 campaign 决策。
