# UGRec_v5_1 调参执行约定

进入本目录的 agent 先读 `README.md`、`docs/调参计划.md`、`docs/指标遵循.md`、`docs/参数接口.md` 和最新 `docs/调参进度.md`；工程状态参考 `docs/验收记录.md`。继承用户全局科研规则及当次对话要求。

- 当前流程是按数据集分别调参，并根据用户每次对话给出的方向自动细化候选。原“先统一结构/容量，再调独立参数”的阶段顺序已取消。学习率、现有 loss 权重和已有模型参数均可按本轮方向独立调整，不要求各数据集共享结构。
- 每次只推进目标数据集。默认可选范围保留 Beauty、Sports、Toys，不自动恢复 CDs，也不为未指定数据集补跑。目标或方向能从当前上下文确定时直接执行；必要信息确实缺失时才询问。
- 本版用于 v5 control 路线的调参。不得修改 UGRec_v5 或旧版本源码/历史结果；公共 cache 只读复用。当前各数据集可从 `structure_hstu_depth_1_s2024` 的对应已审计配置和结果独立起步；其旧四数据集 reject 不回写。
- 探索固定 seed2024。新 trial 先写问题、假设和候选理由，再执行；不默认笛卡尔积、Optuna 大搜索或种子扫描。用户明确要求后可以使用 `joint_training/search.py`；当前 Beauty 的直接 CE 加 HSTU/epoch/recommender.lr 空间已写好但未启动，见 `docs/Optuna搜索.md`。Optuna 分数是选模子集，不能直接当成完整 validation 的采用结果。已有 campaign 仍是 flow control。最终方案冻结后，才显式安排最终方案及关键对照的匹配多种子。
- 每个数据集维护自己的采用配置、parent 和 reference；reference 在本轮方向内固定。主指标为该数据集完整 validation NDCG@10，不以跨数据集均值或旧 2% 联合护栏作晋级条件。小幅单种子差异只作趋势，NLL/Recall 不能代替主指标。
- 用户给出方向即授权在该范围内自动选择参数值、执行必要对照并有限迭代，不为每个常规候选再次索要确认。不得自行扩展到无关方向、新模块或新损失；调整现有 loss 比例不视为新增 loss。改变研究目标、数据处理或推理预算须有用户要求并同步协议。
- 正式结果保留 `prepare/run/summarize/decide` 的可溯源记录要求。单数据集 campaign 必须写 `target_datasets` 和 `selection_rule=target_ndcg10`，只调度该数据集。`epochs` 只在用户方向包含 epoch 时声明，且不少于 40、为 5 的倍数。旧 spec 仍走原来的三数据集和 2% 护栏。不得把单数据集需求套进旧的全组模板，也不得手改 manifest。
- `check` 和 smoke 只验工程。正式训练、选模与 audit 按指标文档执行，不擅改 max_steps/epoch/batch/MC/过滤规则。全量 validation 包含选模用户，不是测试集。
- 结果目录禁止覆盖。先确认 GPU 空闲再选择设备，不中断其他用户进程。失败保留原状态，恢复执行只跳过已审计完成项；半成品用新 id 重做。影响可比性的源码更新后先测试、重验，再重建目标数据集的匹配对照。
- 准备后不要修改运行代码；清单校验源码/配置/数据，每个 campaign 保留 source 快照。不能手改清单绕过指纹，也不能用旧日志补结果。复用测量须标明来源，不算新重复实验。
- 决策写清机制、指标、复杂度、时间/显存与取舍。方向失效、连续两次没有信息增益或达到用户预算时停止；不自动切换方向、数据集、多种子或 test。
- Beauty 上“三层 HSTU + 更慢的 recommender 日程”这一方向已经 reject，采用配置仍是一层 HSTU。进度见 `docs/调参进度.md`。不要自动换数据集或换参数。
