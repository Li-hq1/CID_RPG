# VLAD 精简与残差映射：实验结果（2026-11-09）

本轮按问题主线完成6组探索：去掉扩维/分组/组门控，检验中心残差是否足够，再检验残差后的共享线性映射。发现明确的参数冗余与多簇近重复问题，但尚未得到能一致超过原正收益参考的方案。保留原K1/G2、sqrt(128)、sum作后续比较参考，不替换默认。

## 固定协议

Beauty、seed2024、40epoch/4040更新、batch256、两层HSTU、D128、rec LR=.001、AE LR=.0001、CE+.1AE。AE/catalog单向量、原item reverse RoPE、item内全连接/item间因果/padding隔离、展开长度注意力分母及HSTU后sum均不变。固定4096人selection每5轮选checkpoint，完整22363人validation审计；无test/多种子/新LR网格。每组完整宽度真实cache4更新通过后才正式训练。设计预先保存在各run实际源码快照；阶段A/B的决策与停止范围见decision_A/B.json。

## 实现与必要的澄清

原式是r_k=Σ_g a_gk s_g(u_g-c_k)，u=fc0(x)，保留输入内容，不是只由中心决定。K1/G2的34180个新增参数中，33024个在fc0（96.62%）；其全模型增加仅约1.06%，模块比例不能误写成全模型比例。此前G1仍含D→D映射和门控，本轮才真正去掉。

无分组的单描述子NetVLAD为r_k=a_k(x)(x-c_k)。在正权重、非退化范数的正常数值范围，逐簇L2归一化抵消a_k。因此轻量实现直接使用sqrt(D)*normalize(x-c_k)，删除fc0/组门控/无效assignment，仅保留K×D个中心参数。它是原单描述子公式的方向等价简化，不是完整多描述子NetVLAD，也不宣称有有效soft routing。参考原文arXiv:1511.07247/1811.05014，公式与适用范围见设计.md。

共享映射采用sqrt(D)*normalize(Wr_k)，W为D×D、无bias、所有簇共享；先映射raw残差，再归一化。W恒等初始化、无额外RNG消耗、不会因簇数增加再复制参数。保持实际最终token范数sqrt(128)，避免重引尺度混杂。新增item_vlad_variant=nextvlad|residual|normalized_input、item_vlad_mapping=none|linear，默认旧路径/旧checkpoint兼容；prepare_tokens统一模型和诊断入口。

## 为什么多中心仍没有形成有效分工

- 无扩维分组残差 K4：训练后输入簇平均cos=0.99949598，HSTU后=0.99953926；固定512名selection用户中，将每个中心临时替换为其训练后均值，Top10集合改变0.7812%，顺序改变5.4688%；NDCG10由0.06880778到0.06873491，logp相对L2差0.00013597。
- 轻量残差+共享映射 K4：训练后输入簇平均cos=0.99952060，HSTU后=0.99952102；固定512名selection用户中，将每个中心临时替换为其训练后均值，Top10集合改变1.1719%，顺序改变4.8828%；NDCG10由0.07557582到0.07541223，logp相对L2差0.00020509。

这是选定checkpoint的只读推理干预，中心只在内存临时改变并精确恢复，没有重训、改checkpoint或改选模。原预测与保存的Top10逐位相同，干预预测/指标单独保存并审计。其结果支持“当前模型对簇间中心差异依赖很弱”，但不能证明训练时重复token的dropout效果、优化轨迹或微小中心差异完全没有作用。

几何上每个簇都是同一个x减去一个全局小偏移，输入范数约11，而簇间中心偏离均值的RMS仅约.22；共享线性W能调整共同坐标，却不保证将相近方向变成互补因素。K4映射的输入簇cos仍约.99952。原NeXtVLAD可对组派生特征做输入相关混合，轻量版删除了该能力；这些证据不能推广成“分组普遍无用”。

映射也确实在训练：K1/K4轻量组W相对恒等偏移约19.67%/19.57%，实际token相对未映射方向L2变化20.50%/19.81%；原结构加映射约18.53%。不是断梯度或忘记调用映射。所有有效token最终范数始终sqrt(128)，所以本轮差异不再混入固定输入尺度。

## 成本与取舍

128参数残差K1相对原34180参数模块减少99.63%，全模型从3268500降至3234448（约1.04%）；完整指标损失约1.07%，selection损失约2.39%。它是极简成本对照，不能称已确认等效压缩。

轻量K1映射模块16512参数，较原模块少51.69%；K4映射16896参数，少50.57%，但K4使HSTU处理4倍token。其峰值训练显存约2173.79 MiB，对原K1的926.51 MiB为2.35倍。参数压缩没有降低展开序列带来的主要激活/注意力成本。共享GPU的耗时仅作描述，不能用本轮并发墙钟时间宣称加速。

本轮保留原K1/G2参考及全部候选，不把单种子细小变化升级为稳定收益，不自动换默认。后续若继续，优先围绕“如何让多个token表达输入的不同因素”构建必要对照，而不是再扫K/G或叠加聚合。要验证的是可学习且有差异的内容变换及其必要性；共享映射的局部改善不能证明中心式分簇本身成立。最终方案确定后，再集中对最终方案和关键基线进行多种子验证。
