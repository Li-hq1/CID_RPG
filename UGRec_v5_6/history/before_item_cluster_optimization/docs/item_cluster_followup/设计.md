# 多向量后续：围绕瓶颈逐步推进

客户端日期2026-11-09；用户授权按上一轮分析继续。问题仍是多簇表示能否改善推荐，而不是枚举模块。

阶段A：只把当前逐簇L2归一化后的HSTU输入乘sqrt(D)，匹配基线约sqrt(128)的输入范数。K1/K4各seed2024/40epoch，不改方向、AE、catalog、损失、投影、LR或HSTU。与旧unit K1/K4及单向量基线比较；每组共享初态必须逐位相同，数据/selection匹配。该对照回答尺度变化是否掩盖收益，不能把sqrt(D)当作已证明最优尺度。

之后依据阶段A推进阶段B：在AE内产生未归一化的簇残差，解码前sum，同时同一sum形成catalog；历史使用各簇经原共享normalizer/input_proj的token，HSTU后仍sum。AE几何项作用于原始sum latent，避免单位簇求和与方差目标冲突。先验证必要的共享编码和重建计算图；根据趋势安排相同AE下在HSTU前先合并的对照，区分编码改变与多token交互。具体运行前登记当前证据及对照，不能把多处必需的图变化声称成纯“重建梯度一项”消融。

阶段C仅在B结果需要区分固定sum与学习融合时开展：解码/catalog共用线性concat映射，各块W_k初始化为I、bias0，从sum初态出发，其余B设置不动。历史仍保留多token，HSTU后sum不改；它回答AE item融合问题，不自动证明HSTU输出sum是否最优。明确learner参数和优化器归属，避免仅放进encoder类但实际loss绕过。

优化调整最后做，只有曲线/梯度证据支持时才选一个LR邻域，不先扫K、温度或多种子。仍无新loss/簇ID/额外残差/无关特征。每组固定Beauty/seed2024/40epoch/4040更新/batch256，AE及CE权重保持，4096固定用户每5轮selection选checkpoint，然后完整22363 validation审计，test不读。用selection证据决定下阶段，完整validation只作已选checkpoint的审计，不能用于回选epoch。

每阶段源代码快照、展开配置、数据、初态及选模用户指纹保存，不能覆盖旧目录；必要测试+真实缓存完整宽度4更新后才训。报告各组训练CE、AE项、selection/full NDCG/Recall/NLL、簇差异/输入尺度/原始latent标准差、参数显存，重载及预测重算。旧版保护清单和历史结果hash在本目录。初步单种子趋势不称稳定收益。
